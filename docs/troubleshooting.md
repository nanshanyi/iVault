# 出问题怎么查

[← 返回 README](../README.md)

## 先看日志

三处日志，覆盖三种场景：

| 场景 | 看哪里 | 保留多久 |
|---|---|---|
| 某次备份/恢复为什么失败 | 界面「备份任务 → 任务历史」状态旁的**日志**按钮 | 随任务记录保存，删记录即删日志 |
| 配对 / 无线通道为什么不工作 | `docker compose logs ivault`，找 `[usbmuxd]` `[netmuxd]` 前缀 | 容器日志，10MB×3 自动轮转 |
| 说不清哪里不对 | 设置 → 关于 → **诊断信息 → 复制** | 内存里最近 200 条告警 |

细节：

- **任务日志落库**。`idevicebackup2` 的输出（含时间戳与完整命令行）在任务结束时写进 `backups` 表的 `log` 列，只留末尾约 2.4 万字符。以前这些只活在内存里，任务一结束就没了，事后只能看到一条 FAILED。
- **容器日志一处看全**。`usbmuxd` 和 `netmuxd` 不再写 `/var/log/*.log`（容器里没有持久卷，重启即丢），而是带前缀直接进 stdout。想看 usbmuxd 的详细过程：`IVAULT_USBMUXD_VERBOSE=1`。
- **轮询不再刷屏**。前端每 6 秒刷新会打 5 个请求（页签切到后台时暂停），开着页面一天七万多条；`uvicorn` 的 access log 已关掉，改由中间件只记**出错、写操作、超过 1.5 秒的请求**。
- **诊断信息**是纯文本，含版本、系统、运行时长、设备与连接方式、最近备份记录与失败原因、最近 200 条告警。留一份在手上，过几天回来排查也够用。

## 进度一直停在 0%

iOS 16.1 起，开始备份前手机可能要求输入锁屏密码。任务卡显示「等待输入锁屏密码」、日志里有 `*** Waiting for passcode to be entered on the device ***` 时，去 iPhone 上输入锁屏密码。

输入后手机还要准备一段时间才开始传数据，可能好几分钟没有任何输出，进度一直是 0%，这是正常的。这期间日志每分钟记一条「仍在等待手机」，看到「开始传输数据」那一行就说明过了这一步。

## 插上 iPhone 却一直显示离线

容器内的 `usbmuxd` 收不到 USB 热插拔事件（`libusb` 的 hotplug 订阅的是 `udevd` 的转发组，容器里没有 `udevd`，宿主也不会跨 netns 转发），设备表在容器启动瞬间就冻结了。镜像里的 `scripts/usb-watchdog.py` 负责兜底：检测到设备接入就重启 `usbmuxd` 重扫，所以**插线后要等 1~2 秒**页面才会变在线。

按现象分三种情况：

| 现象 | 原因 | 处理 |
|---|---|---|
| 插线后 1~2 秒自己变在线 | 正常，看护在重启 `usbmuxd` 重扫 | 无需处理 |
| 日志有 `[usb-watchdog] ... 重新扫描`，紧接着 `libusb couldn't open USB device ... errno=2` | compose 里用 `devices:` 挂的 USB 总线，那是**容器创建时的设备节点快照**，插拔后新节点在容器内不存在 | 改成 `volumes: - /dev/bus/usb:/dev/bus/usb` |
| 拔线后手机仍在广播 mDNS，但页面显示离线 | 无线通道探活失败 | 见下一节「无线（Wi-Fi）设备一直不出现」 |

看护由 `IVAULT_USB_WATCHDOG` 控制，默认开启；设成 `0` 会回到旧行为（容器运行中插线不识别，需要重启容器）。

## 无线（Wi-Fi）设备一直不出现

先分清两件事：手机**有没有广播**，和**本机客户端连的是谁**。

```sh
# 1) 手机侧：应在同一局域网内看到 _apple-mobdev2._tcp 记录（含你的 iPhone）
dns-sd -B _apple-mobdev2._tcp local.        # macOS；Linux 用 avahi-browse -rt _apple-mobdev2._tcp
nc -z <手机IP> 62078                        # lockdownd 端口可达

# 2) 本机侧：设备列表里应能看到网络设备
idevice_id -n
```

查看 `[netmuxd]` 日志里的 `Adding network device <UDID>`：有这一行说明发现成功，问题在客户端侧。

**最常见的坑：`USBMUXD_SOCKET_ADDRESS` 少了 `UNIX:` 前缀。** `libusbmuxd` 的 `connect_usbmuxd_socket()` 只认两种写法——`UNIX:<路径>`（大写，`strncmp` 比较）和 `<host>:<port>`。裸路径 `/var/run/usbmuxd-net` 两个分支都不匹配，会**静默回落**到 `/var/run/usbmuxd`：于是所有 `idevice_*` 拿到的是原生 `usbmuxd` 的设备表，USB 一切正常、Wi-Fi 设备永远为空，而且**退出码恒为 0、不报任何错**。`entrypoint.sh` 里已按 `UNIX:$WIFI_SOCKET` 导出，并带一条防回归探针（指向不存在的 socket 若仍返回 0 就告警）。

三条自查，按顺序排掉：

| 检查 | 期望 | 不符合说明 |
|---|---|---|
| `echo $USBMUXD_SOCKET_ADDRESS` | `UNIX:/var/run/usbmuxd-net` | 缺前缀 → 客户端连错 socket |
| `idevice_id -l`（unset 该变量） | 插线时能列出 USB 设备 | 工具链或 usbmuxd 有问题 |
| `idevice_id -n` | 无线在线时列出 UDID | 需先看 `[netmuxd]` 是否 `Adding network device` |

设备发现成功后仍需通过探活：`idevicepair -n -u <UDID> validate` 返回 0 才算在线。失败说明手机锁屏休眠、已离开局域网，或配对证书被清掉。探活结果有缓存（见下文「在线状态为什么会滞后」），手动跑上面的命令看到在线、页面还显示离线时，等 2 分钟或直接点「立即备份」。

### 在线状态为什么会滞后

无线设备要探活才算在线，避免把 mDNS 残留的失效条目误显示成「在线」。探活每次都要新建一条网络连接，所以结果会缓存：在线的 60 秒内不重探，连不上的按 30 → 60 → 120 秒退避。代价是手机离开局域网后最多 60 秒才显示离线，休眠的手机醒来后最多约 2 分钟才显示在线。备份、恢复、改加密和定时备份开跑前都会对目标设备现探一次，不受这个延迟影响。

## 定时备份为什么没有跑

调度器从设定时刻到当天午夜每 20 秒检查一次，满足下面全部条件才会对一台设备开跑：

- 设定时刻之后它还没有成功备份过（手动备份也算），也没有被手动取消过
- 当天失败不到 3 次，且距上次失败已超过 30 分钟
- 在线，且没有别的任务占着它（开跑前会对这台设备再确认一次是否真在线）
- 电量不低于 `IVAULT_MIN_BATTERY`，或者正在充电 / 接着电源

不满足就等下一轮，不写失败记录。电量不足时日志里每台设备每天只记一条 `定时备份暂缓`，`docker compose logs ivault | grep 定时备份` 能看到。

## 卡片上的电量不是最新的

查一次电量要拉起一个 `ideviceinfo`。无线设备每查一次都要新建网络连接，查多了既慢又费手机电，所以电量是后台采样的，不是每次刷新页面都去查：

| 情况 | 采样频率 |
|---|---|
| 页面开着且在前台，USB 设备 | 每分钟一次 |
| 页面开着且在前台，无线设备 | 每 10 分钟一次 |
| 没有页面开着，或页签在后台 | 不定时采样 |
| 定时备份要判断电量时 | 复用上面的读数，过期了才现查（USB 超过 1 分钟、无线超过 10 分钟） |
| 点「立即备份」时 | 总是现查 |
| 插拔线、换连接方式、任务刚结束 | 作废旧读数，下一轮重新采 |

读数超过 2 分钟，卡片悬停提示和设备详情里会标出是几分钟前读到的。
